## Codebase Patterns
- Routes in this project use raw `knex` queries directly against Postgres (see `ActiveReservations/routes.ts`, `PlaceReservation/routes.ts`) — not the `supabase`/`readmodel` helper shown in the generic `build-state-view` SKILL.md template. Follow the existing routes.ts pattern in the slice's own context folder over the skill's generic example when they differ.
- Migrations live at repo root `migrations/V{n}__*.sql` (not `supabase/migrations/` as the skill template says). Append-only — never edit an existing migration, add a new `V{n}` file.
- `.build-kit/.eventmodelers/config.json` is absent in this repo (only `install-manifest.json` exists there) — board sync / `update-slice-status` / MCP calls are skipped for this project; slice status is tracked locally in `.build-kit/.slices/<context>/index.json` only.
- `npm run run:checks -- --staged` mirrors the pre-commit hook exactly (staged-only); plain `npm run run:checks` checks ALL uncommitted changes including unrelated pre-existing working-tree modifications — use `--staged` after `git add`ing only the intended slice files to get an accurate pass/fail signal.
- slice.json readmodel/screen `fields[]` can rename a value relative to the underlying event's own field name (e.g. event field `NumberOfPeople` exposed as read-model/screen field `PartySize`) — the DB column and API/JSON field follow the slice.json name, but the event's TS type field itself is untouched unless the event-producing slice (out of scope here) is itself Planned.
- `server.ts` auto-discovers `routes.ts` files by glob — no manual import/wiring step needed after creating a new slice's `routes.ts`.
- `.build-kit/lib/checks/10-slice-scope.cjs` rejects any commit that mixes `.build-kit/.slices/**` status-file changes with slice code — commit the slice implementation first, then a separate `chore: mark ... Done` commit for the `index.json` flip.

  - Pre-existing unrelated uncommitted changes were present in the working tree at the start of this iteration (OpenAPI doc comments added to `PlaceReservation/routes.ts` and `ActiveReservations/routes.ts`, plus new synced slice folders from a prior `load-slice` run) — left untouched and unstaged; only this slice's own files were staged and committed.
